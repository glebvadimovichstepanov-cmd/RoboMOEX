# Контракты данных, сигналов и исполнения

## Данные и календарь

1. Внутри системы timestamp — timezone-aware UTC. Наивное время отвергается;
   только MOEX adapter знает, что поле begin API задано по московскому времени.
2. Минутный бар — полуинтервал [open_time, close_time). Свеча недоступна до
   close_time. На незакрытых свечах решения не принимаются.
3. OHLC положительный и конечный, volume конечный и неотрицательный. Проверяются
   границы OHLC, последовательность, отсутствие повторов и перекрытий.
4. Для ручных CSV сессии поставляет оператор как версионируемый CSV. Для
   загрузки MOEX ISS расписание строится через `/iss/calendars/stock.json`:
   учитываются `is_traded=1`, праздники и перенесённые рабочие дни. v1 выбирает
   одну непрерывную основную сессию на московскую торговую дату; часы задаются
   параметрами CLI. Утренние/вечерние сессии и клиринг не смешиваются молча.
5. В пределах заданной сессии обязательна каждая закрытая минута. Пропуск —
   ошибка всего набора. Это консервативная политика для ликвидных инструментов;
   разрешать отсутствие сделок в отдельной минуте нужно отдельной политикой,
   а не автоматическим заполнением цен.
6. 15m buckets привязаны к открытию сессии. Дневной бар содержит только выбранную
   сессию. Последний укороченный bucket допустим на явной границе сессии.
7. Для paper внешние данные должны быть не старше 2 минут и текущая дата/время
   должна принадлежать заданной сессии. Синтетический demo — явно помеченный
   replay, без претензии на свежие биржевые данные.
8. Cache сохраняется одним атомарно заменяемым JSON с CSV, query и SHA256.
   Несовпадение query, повреждение файла или ошибка API останавливают запуск.

## Причинность

Индикаторы вычисляются только на уже закрытых барах. Прогрев не заполняется.
Для совмещения ТФ merge_asof(direction=backward) выполняется по **close_time**.
Тесты обрезают историю в середине дня и 15m интервала и проверяют равенство
прошлых сигналов; отдельно изменяют будущие цены.

Сигнал на баре i может привести к входу только на открытии следующего
непосредственно примыкающего минутного бара. Через разрыв сессий сигнал истекает.
Открытая позиция при этом может переноситься; гэп учитывается на следующем баре.

## Симуляция исполнения

- Только long; целое заданное количество лотов. Нет маржи, short и частичного
  входа при нехватке денег. Недостаточный cash считается rejected entry.
- Покупка по следующему open с заданным неблагоприятным slippage; округление
  покупки вверх до tick_size, продажи вниз. Комиссия начисляется с обеих сторон.
- SL/TP считаются от фактической модельной цены входа и ATR сигнального бара.
- Защита проверяется независимо от новых сигналов. Gap через SL исполняется
  по open, а не по недоступной цене стопа. TP при gap учитывает open.
- Если внутри бара могли сработать оба уровня, выбирается SL. Порядок тиков
  внутри OHLC неизвестен; модель намеренно консервативна.
- На том же баре после выхода новый вход не создаётся. На последнем баре нет
  фиктивной ликвидации: позиция помечается открытой и входит в mark-to-market.
- Это OHLC-симулятор, не доказательство реального исполнения: стакан, очередь,
  частичные исполнения, funding, corporate actions и ликвидность не моделируются.

## Метрики и воспроизводимость

PnL закрытой сделки учитывает обе комиссии. Equity учитывает открытые позиции.
Max drawdown положительный (0.2 = 20%). Sharpe использует дневные наблюдения по
московским датам, sample std и коэффициент sqrt(252). На недостаточной выборке
или нулевой дисперсии возвращается null. Не используется частота потерянного
numpy индекса и не скрываются исключения расчёта.

Одинаковые code revision, lockfile, входные CSV, конфигурация и cutoff дают
одинаковые результаты. В report.json нет случайного run ID или текущего времени
при историческом запуске. Хеши входных данных и расписания включены в отчёт.
Результаты demo — проверка поведения, не свидетельство доходности.

## Граница прогнозирования

`future_forecast` принимает уже созданный совместимый predictor, использует
полный target и требует forecast.start_date == start + len(context).
Регулярность сетки проверяется; ночные/выходные не заполняются доходностями.
Преобразование log returns в цены происходит по каждому sample path до квантилей.
`verify_artifact` проверяет SHA256 до загрузки модели. Сам загрузчик модели,
checkpoint, обучение и benchmark Lag-Llama не входят в выбранный релиз.
