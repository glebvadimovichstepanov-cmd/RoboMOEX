## Воспроизводимые команды из корня RoboMOEX

Используйте Python из .venv. Дополнительные библиотеки не добавлены.

```powershell
.\.venv\Scripts\python.exe -m robomoex.cli --mode backtest --demo --output results/refactor_demo
.\.venv\Scripts\python.exe -m robomoex.context --cache-dir results/context_cache_v2 --start 2025-01-01
.\.venv\Scripts\python.exe -m robomoex.research --refresh --output results/research_v2
.\.venv\Scripts\python.exe -m robomoex.research --output results/research_v2
```

Последняя команда работает без сети на сохранённом кеше. --refresh обновляет внешний
контекст, но не минутный кеш SNGS; для него остаётся отдельный --download старого CLI.
Дневная загрузка исключает незавершённую текущую московскую дату. Дата ряда —
метка наблюдения, временные метки наблюдения события и свечей — UTC.
Внешний дневной контекст консервативно сдвинут на следующую московскую дату;
точное время публикации рыночных рядов пока не реконструировано.

Новый прогон: 4 последовательных окна и последние 60 баров отдельно, train начинается
с 260 баров. Порог выбирается только по train; при менее 3 сделок используются
исходные параметры с отметкой insufficient_training_trades. Каждый сегмент начинается
со 100000, позиции ликвидируются в конце сегмента с издержками; это явно заданная
конвенция исследования. Сводная доходность независимых сегментов не заявляется.

## Доступ AlgoPack

Добавлен robomoex.algopack: токен читается из MOEX_API_TOKEN либо MOEX_TOKEN_FILE
(по умолчанию .secrets/moex.token). .secrets исключён из git. Bearer передаётся только
на HTTPS apim.moex.com/iss, переадресации запрещены; TLS-проверка обязательна.
Предоставленный ключ сохранён локально, его значение не входит в отчёты.

```powershell
.\.venv\Scripts\python.exe -m robomoex.algopack
.\.venv\Scripts\python.exe -m robomoex.context --authenticated --cache-dir results/algopack_context
```

Проверка пяти маршрутов (свечи, сделки, стакан, obstats, календарь) остановилась
на SSLCertVerificationError до ответа об авторизации. Права тарифа не подтверждены.
Для дополнительного CA можно задать MOEX_CA_FILE с путём к PEM;
отключение проверки сертификата не применяется. Нужна информация о прокси/VPN/CA.

Документация авторизации: https://moexalgo.github.io/.
Полученный ключ не означает автоматического доступа ко всем продуктам или архиву стаканов.

### TLS исправлен

Прямое соединение предъявляет Russian Trusted Sub CA / Russian Trusted Root CA.
Сертификат Kaspersky на скриншоте относится к браузерной HTTPS-инспекции.
Корневой сертификат получен с https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
по проверенному HTTPS; SHA256 DER:
`d26d2d0231b7c39f92cc738512ba54103519e4405d68b5bd703e9788ca8ecf31`.
Источник и порядок перехода описаны MOEX:
https://www.moex.com/kak-sohranit-dostup-k-servisam-birzhi.

Файл .secrets/moex-ca.pem загружается только MOEX-клиентом через SSLContext;
MOEX_CA_FILE позволяет указать другой путь. Системное хранилище не менялось.
CERT_REQUIRED, проверка имени сервера и запрет редиректов сохранены.

Повторная проверка с ключом: свечи — 500 записей первой страницы, сделки — 5000.
Это размеры ответов, а не полный архив. Стакан, obstats и календарь не вернули
ожидаемый JSON; их права доступа не подтверждены. Авторизованное обновление
контекста выполнено, результат в results/algopack_context/status.json.
Исследовательские блокировки отсутствующего контекста продолжают действовать.
