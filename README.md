## Быстрый старт

Python 3.12.14 и uv 0.7.13. Из корня проекта:

```sh
uv sync --frozen --extra dev
uv run --frozen robomoex
uv run --frozen robomoex --mode backtest --demo --output results/backtest
uv run --frozen pytest
uv run --frozen ruff check .
```

Без аргументов выполняется **paper replay на синтетических данных**. Интернет,
токены, брокерский счёт и GPU не нужны. Это демонстрация программы, не рыночный
результат. `--mode live` возвращает ненулевой код до чтения входных файлов.

`paper` здесь означает одноразовый прогон симулятора; это ещё не постоянно
работающий paper-сервис с восстановлением состояния. Для внешних данных этот
режим требует свежей последней закрытой свечи и активной явно заданной сессии.

## Свои данные

CSV свечей: `open_time,close_time,open,high,low,close,volume`.
Время обязательно содержит UTC offset, например `2026-08-20T10:00:00+03:00`.
Исходный интервал — одна минута; `close_time` — исключающая правая граница.
CSV расписания: `open_time,close_time`; одна выбранная непрерывная сессия на день.
Для `--input` расписание по-прежнему задаётся явно. Для `--download` его можно
не передавать: RoboMOEX получает календарь фондового рынка из MOEX ISS
(`https://apim.moex.com/iss/calendars/stock.json`), учитывает переносы рабочих
дней и праздники и строит основную сессию 09:50–18:50 по Москве.

```sh
uv run --frozen robomoex --mode backtest --input candles.csv --sessions sessions.csv --config configs/default.toml
uv run --frozen robomoex --mode backtest --download --symbol SBER --board TQBR --start 2026-08-20T10:00:00+03:00 --as-of 2026-08-20T18:00:00+03:00 --cache cache/sber.json
```

Вторая команда использует официальный календарь MOEX автоматически. Часы можно
переопределить параметрами `--calendar-open` и `--calendar-close`. В v1 загрузка публичных
обычных свечей через MOEX ISS; новый AlgoPack-загрузчик запускается отдельно,
как описано в ALGOPACK.md.
Сессии должны точно покрывать выбранный диапазон: любые пропущенные минуты,
дубли, неверный OHLC или бары вне расписания останавливают расчёт.

При указании `--cache cache/SBER.1m.json` кеш расширяется инкрементально: при
следующем запуске запрашиваются только минуты до начала или после конца уже
сохранённого диапазона. Рядом сохраняются производные кеши `*.15m.json`,
`*.1h.json` и `*.1d.json`, построенные из 1m. Для первичной загрузки с января
2025 года укажите `--start 2025-01-01T00:00:00+03:00`; последующие запуски с
новым `--as-of` дозагрузят только хвост.

Выход: `report.json` (версии, хеши данных/расписания, параметры, метрики),
`trades.json` (закрытые сделки), `equity.csv` (капитал по барам).
Точный исполняемый код определяется commit SHA релиза и `uv.lock`.

## Границы релиза

Один инструмент, long-only, фиксированное число целых лотов. Основная стратегия —
confluence (1 минута / 15 минут / выбранная дневная сессия). Она не объявляется
прибыльной. Подбор параметров на всей истории и экспериментальные модели не
входят в исполняемый торговый путь. Функция `forecast.future_forecast` исправляет
контракт будущего прогноза для совместимых предикторов, но Lag-Llama/GPU стек
не требуется и не скачивается.

Дальнейшие этапы: брокерское исполнение, журнал состояний, восстановление,
обязательный риск-контроль, эксплуатация и испытания на реальных данных.
